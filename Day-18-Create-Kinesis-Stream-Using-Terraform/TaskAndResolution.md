# Project Overview

As part of a real-time analytics modernization initiative, the platform engineering team needed to provision an Amazon Kinesis Data Stream to ingest and process streaming data generated by applications, monitoring systems, and business services.

The objective was to:

* Create a Kinesis Data Stream.
* Configure the stream using Terraform.
* Ensure the stream is deployed successfully.
* Validate that Terraform state and infrastructure remain synchronized.
* Confirm that `terraform plan` returns **No changes**, ensuring configuration consistency.

This deployment demonstrates Infrastructure as Code (IaC) principles and real-time streaming architecture implementation.

```hcl
shard_count = 1
```

Creates one shard for data ingestion and processing.

---

# Understanding Kinesis Shards

A shard is the throughput unit of a Kinesis stream.

Each shard supports:

```text
1 MB/sec Write Throughput
2 MB/sec Read Throughput
1000 Records/sec Writes
```

Architecture:

```text
Kinesis Stream
      │
      ├── Shard-1
      ├── Shard-2
      └── Shard-3
```

More shards = More throughput.
